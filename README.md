# 深圳/浙江税务 一键填表登录

电子税务局 tpass 登录页的填表助手：点一下公司名，自动填好「纳税人识别号 / 手机号 / 密码」并帮你点登录。

适合手上管着多家公司、每次登录都要翻税号的情况。

> 验证码（文字点选）**仍然要自己点**，脚本不做识别。原因见文末。



---

## 装

1. 浏览器装 [Tampermonkey](https://www.tampermonkey.net/)
2. 新建脚本，把 `etax_login.js` 全文粘进去，保存
3. 打开深圳或浙江的 **tpass 登录页**，会自动弹出「添加公司」窗口

> 脚本只在 tpass 登录页生效。登录成功后跳到 etax.* 内网页面就不再注入任何东西，不干扰后续操作。

---

## 第一次用：填公司

弹窗五个字段：

| 字段     | 说明                 |
| ------ | ------------------ |
| 公司简称   | 面板上显示的名字，随便起，好认就行  |
| 归属城市   | 深圳 / 浙江            |
| 纳税人识别号 | 18 位统一社会信用代码       |
| 手机号    | 登录用的手机号            |
| 密码     | 登录密码，可勾「显示」核对有没有打错 |

三个按钮：

- **继续添加** — 存好当前这条，清空表单接着填下一家（城市会保留上次的选择）
- **取消** — 丢弃当前这条，关掉窗口
- **确定** — 存好当前这条，关掉窗口

录完一家点「继续添加」，录完最后一家点「确定」。中途取消也没关系，面板底部还有「➕ 添加公司」。

### 公司多的话：批量导入

窗口底部有一行「📥 批量导入（粘贴 JSON / 每行一条）」，点开是个文本框，两种格式都吃：

**JSON 数组**（推荐，就是 `accounts.local.json` 的格式）

```json
[
  { "name": "公司甲", "site": "shenzhen", "taxId": "91440300XXXXXXXXXX", "phone": "13800138000", "password": "pwd1" },
  { "name": "公司乙", "site": "zhejiang", "taxId": "91330100XXXXXXXXXX", "phone": "13900139000", "password": "pwd2" }
]
```

**每行一条**（用 Tab 或逗号分隔）

```
公司甲	91440300XXXXXXXXXX	13800138000	pwd1	深圳
公司乙	91330100XXXXXXXXXX	13900139000	pwd2	浙江
```

点「导入（同名覆盖）」一次性灌进去。重复导入不会产生重复条目——公司简称相同的会被覆盖更新，其余追加。

> `site` 认得 `shenzhen` / `深圳` / `zhejiang` / `浙江` 几种写法，中英文混着填也没问题。

## 日常用

1. 打开 tpass 登录页
2. 点右上角「📋 一键填表」
3. 点公司名 → 三字段自动填好 → 自动点登录
4. **手动点选验证码** → 登录完成

在深圳站选浙江的公司，脚本会先跳到浙江站，跳过去接着自动填，不用再点一次。

另外两个入口：

- Tampermonkey 图标 → 脚本菜单「➕ 添加公司」，不在登录页也能加
- 面板里每条公司右侧的「✕」可以删掉（会先问一句）

## 数据存在哪

- 存在 Tampermonkey 的 `GM_setValue` 里，键名 `etax_accounts_v1`
- **更新脚本不会丢**，只有卸载脚本才会清掉
- 明文存在本机浏览器，不进源码、不上传任何服务器
- 所以：只在自己的电脑上配，别用公共电脑

脚本代码里 `CONFIG.accounts` 是空数组，真实账号一条都没写进去 —— 这份代码可以直接公开，不用担心泄露。

## 常见问题

**为什么不做验证码自动识别？**  
试过。本地 ddddocr + 旋转模板匹配，实测成功率约 9%，等于不能用。真要全自动得接多模态大模型或打码平台，成本不划算。脚本只帮你省掉打三遍字段的功夫。

**换电脑 / 重装浏览器怎么办？**  
数据跟着浏览器走，换机器要重新录一遍。公司多的话，建议录完在第一台机器上把税号密码另存一份（比如 `accounts.local.json`），换机器时照着填。

**填完没反应？**  
登录页是 Vue 动态渲染的，脚本会等表单出现（最多 15 秒）才注入按钮。如果一直不出现，多半是页面改版导致选择器失效，见下面的选择器表，改一下就行。

**点了公司名跳到别的站，但没自动填？**  
跨站靠本地存储传一次性的待填标记，2 分钟内有效。超时了就手动再点一次公司名。

## 技术细节

**生效范围**

```
https://tpass.shenzhen.chinatax.gov.cn:8443/*
https://tpass.zhejiang.chinatax.gov.cn:8443/*
```

**表单选择器**（页面是 Element UI）

| 字段     | 选择器                                 |
| ------ | ----------------------------------- |
| 纳税人识别号 | `.el-autocomplete .el-input__inner` |
| 手机号    | `.mobileInp > .el-input__inner`     |
| 密码     | `.pwdInp > .el-input__inner`        |
| 登录按钮   | `.el-col > .el-button`              |

> 注意 `.mobileInp > .el-input__inner` 是**直接子元素**。如果哪天页面在这中间多套一层 div，填表会静默失败（表现为点了没反应），改选择器即可。

**跨站跳转怎么传的**  
不走 URL 参数——那样公司名会留在地址栏和浏览器历史里。改用 `GM_setValue` 写一个 2 分钟有效的待填标记，目标页读完立刻删。只有本地存储写不进去时才退回 URL 参数兜底，且读完后会立刻擦掉地址栏。

## 归档：验证码自动识别为什么放弃

试过本地 ddddocr + 旋转模板匹配，**实测成功率约 9%（1/11、1/10）**，判定不可用：

- 验证码固定 4 个字，提示条与大图是同一字形，差异是旋转 + 删除线
- ddddocr 的 det 检测字位置较可靠但偶发漏检；连通域兜底会引入背景假框
- CCOEFF / IoU 两种匹配的 top1-top2 区分度只有 0.005~0.07，远低于可靠阈值
- 「少笔画字 ⊂ 多笔画字」会让 CCOEFF 虚高，换 IoU 也没改善

想要真·全自动，只能换多模态大模型识图或第三方打码平台。
